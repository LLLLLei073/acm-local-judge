# 训练与出题工作台

重构继续使用现有题库、账号、比赛、提交快照与本地数据目录。界面分为选手训练台 `/` 与管理端 `/admin`。

## 选手训练

- 首页展示本人的累计提交、已解决与待攻克题目、近七天提交活动（UTC 日期）。统计基于完整个人历史，题库解决状态不会被后来的失败覆盖。
- 「待攻克」链接定位最近仍未解决的题目；没有待攻克记录时，按已有 AC 难度的邻近值推荐未解决题目。推荐由真实题库与记录计算，不使用 AI，也不虚构进度。
- 筛选支持类型、难度、比赛和解题状态；排序支持难度与通过人数。表格行可用 Tab 聚焦、Enter 打开。
- 代码草稿按账号 ID 与题目 ID 分别保存。浏览器存储不足时会提示备份。旧版未区分账号的草稿不会自动分配给其他账号。
- 初次打开题目提供读写模板；完整标准答案保留在管理端。编辑器支持字号、换行、全选与 Ctrl/Cmd+Enter 提交。
- 比赛按阶段筛选；排行榜高亮自己的记录，搜索不揭示匿名用户身份。个人设置分为资料与隐私、账号安全、Codeforces 三区。

## 运行证据

两端共用结果面板与测试点详情组件。结果面板展示测试进度、CPU/内存峰值、限额使用比例、针对判定的检查建议，并能定位首个失败点。没有输出不等于未运行，CPU 时间也不等于墙钟时间。

实时事件流断开或收到无效消息后，页面自动改用轮询获取同一提交；暂时失败后继续重试。切换结果或卸载组件会清理连接，旧响应不能覆盖新页面。取消仅对提交本人和管理员开放。

测试点详情分为通信时间线、实例与输出。时间线支持参与者与内容过滤、每页 100 段；日志可导出为 JSON，包含页面已获授权读取的完整测试点内容。

## 出题管理

- 工作台按发布、评级与近期验证情况筛选，支持搜索与本机未保存草稿恢复。
- 准备清单检查题面、评级、数据命名、资源限制、必需判题程序和标准答案。清单仅检查准备条件；标准答案存在不等于已实际验证，历史验证也可能来自旧版本。
- Markdown 可在编辑和预览间切换。测试数据采用索引列表与单点编辑，避免大量文本域同时挂载；可调整顺序，第一个测试点仍作为公开样例。
- 批量载入先核对 `.in/.ans` 配对，显示新增与替换数量，再应用到草稿。失败时不修改已有数据；合法空输入/空答案保留。
- 多进程通信流程同时提供时序图和表格。点击时序步骤可回到相应编辑项；即时检查重复成员、越界编号、向已关闭输入发送、前向消息引用和缺失校验。后端仍做最终校验。
- AI 起草题面和生成强化输入后先预览，再选择应用。强化输入由标准答案计算答案，人工仍需核对输入是否满足题目约束。
- 管理员验题使用独立的 `purpose: verify`，即使浏览器同时登录选手账号，也不把验题记入个人训练。原快照重评与整题按当前数据重测保持不同语义。
- 暴力对拍展示失败证据；CE/WA/RE 不能证明复杂度被卡住，TLE 也要结合 CPU 与墙钟分析。
- 用户管理可按姓名、学号、邮箱、CF 账号搜索；顶部运行状态每 15 秒更新 Worker、运行数和排队数。

## 开发验证

前端 `pnpm test` 验证训练统计、草稿键、数据配对、流程检查、SSE 与轮询生命周期。`pnpm build` 做类型检查与生产构建。

`scripts/verify.ps1` 和 `scripts/verify.sh` 同时包含前端行为检查与既有真实程序测试。测试服务应使用独立的发布目录与 `ACM_DATA`，避免占用源项目构建 DLL 或改动业务数据。

Windows 启动脚本以无需登录的 `/healthz` 识别已有服务，支持 `ACM_PORT`；自动打开浏览器不再依赖需要登录的 `/api/environment`。
